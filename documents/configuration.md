# UyirKappan Centralized Configuration & Environment Hardening Specification
**Phase 21 Architecture & Operational Reference**

---

## 1. Overview & Objectives

In early phases of UyirKappan, environment variables and configuration constants were read ad-hoc across various sub-modules (e.g., `process.env.PORT`, `process.env.DATA_STORE_MODE`, `process.env.TRAFFIC_PROVIDER`).

Phase 21 establishes an **authoritative, centralized configuration layer** located at:
`backend/src/config/index.js`

### Primary Objectives:
1. **Single Source of Truth**: All environment-dependent parameters are parsed, normalized, frozen, and exposed through a single authoritative configuration module.
2. **Fail-Fast Validation**: Startup terminates with clear, descriptive errors if required parameters are missing or invalid (e.g., non-numeric ports, invalid datastore modes, unprovided MongoDB URIs in MongoDB mode, or insecure default JWT secrets in production).
3. **Strict Secrets Redaction**: MongoDB passwords, JWT keys, and API tokens are never exposed via diagnostics, logs, or API endpoints.
4. **Clean Backwards Compatibility**: Legacy callers importing `backend/src/config/environment.js` delegate seamlessly to `config/index.js` with zero breaking changes to existing endpoints or test suites.
5. **Multi-App Alignment**: Clear documentation and mapping across backend services, mobile apps (`bystander_app`, `driver_app`), and web dashboards (`hospital-dashboard`, `research-portal`).

---

## 2. Configuration Groups & Authoritative Schema

The centralized configuration object (`config`) is frozen (`Object.freeze`) and organized into logical domains:

```
config
 ├── environment          (nodeEnv, isDevelopment, isTest, isProduction)
 ├── server               (host, port, baseUrl, corsOrigins, autoKillOnConflict)
 ├── database             (mode, mongoUri, timeoutMs, isMemory, isMongo)
 ├── traffic              (provider, fallbackProvider, googleMapsApiKey, mappls..., googleConfigured, mapplsConfigured)
 ├── auth                 (jwtSecret, jwtExpiresIn, driverResponseTimeoutMs, bcryptSaltRounds)
 ├── routing              (approachSpeedKmph, freeFlowSpeedKmph, toleranceKm, bounds)
 ├── socket               (corsOrigins, pingTimeout, pingInterval)
 ├── datasets             (datasetDir, roadKmlPath, baselineDatasetPath, fleetSourceClassification, baselineClassification)
 └── logging              (level, silent)
```

## 3. Strict Validation & Fail-Fast Rules

| Setting | Allowed Values / Rule | Development / Test Fallback | Production Behavior |
| :--- | :--- | :--- | :--- |
| `PORT` | Integer `1` to `65535` | Defaults to `5000` if invalid or empty | Must be valid integer |
| `DATA_STORE_MODE` | `'memory'`, `'mongodb'` | Defaults to `'memory'` | Throws if invalid value provided |
| `MONGODB_URI` | Valid MongoDB connection string | Required ONLY if `DATA_STORE_MODE=mongodb` | **Throws immediately** if mode is `mongodb` and URI is missing |
| `TRAFFIC_PROVIDER` | `'simulation'`, `'google'`, `'mappls'` | Defaults to `'simulation'` | Throws if invalid provider specified |
| `TRAFFIC_PROVIDER_FALLBACK` | `'none'`, `'simulation'` | Defaults to `'none'` | Falls back safely when configured |
| `JWT_SECRET` | Strong secret string | `uyirkappan-dev-secret-change-me` allowed in dev/test | **CRITICAL SECURITY ERROR**: Throws immediately if default secret used |
| `CORS_ORIGINS` | Comma-separated domains or `'*'` | Defaults to `'*'` | Comma-separated whitelist recommended |

## 4. Secret Masking & Diagnostic Endpoints

### 4.1 Masking Utilities
The configuration layer provides `maskMongoUri(uri)` which masks any embedded username and password credentials:
- Raw URI: `mongodb+srv://admin:mySecretPassword123@cluster0.abc.mongodb.net/uyirkappan`
- Masked URI: `mongodb+srv://admin:*****@cluster0.abc.mongodb.net/uyirkappan`

### 4.2 Diagnostic Endpoint: `GET /api/system/config`
To assist DevOps, health checks, and dashboard telemetry without compromising security, `GET /api/system/config` exposes the sanitized schema generated by `config.getSanitized()`:

## 6. Development, Testing, and Production Profiles

### 6.1 Development Mode (`NODE_ENV=development`)
- Uses local `backend/.env` file.
- `DATA_STORE_MODE=memory` by default for zero-dependency execution.
- Can be set to `DATA_STORE_MODE=mongodb` with local or Atlas URI.
- In-memory simulated traffic provider active by default.
- Permissive CORS for cross-origin development on local ports.

### 6.2 Test Mode (`NODE_ENV=test`)
- Configurable programmatically via `createConfig(customEnv)`.
- Automatic port allocation or mock ports for concurrent test isolation.
- `LOG_SILENT=true` suppresses noise during automated test runs.
- Tested across both `DATA_STORE_MODE=memory` and `DATA_STORE_MODE=mongodb`.

### 6.3 Production Mode (`NODE_ENV=production`)
- Requires explicit `JWT_SECRET` (default developer secret rejected at startup).
- `DATA_STORE_MODE=mongodb` requires explicit `MONGODB_URI`.
- CORS restricted to defined domain whitelist.
- All secrets sanitized before any diagnostic rendering.
